## 0. 미아 제안 (슬랙 원문 요지)

1. 법은 조문만으로 안 끝난다 — 시행령·규칙·예규·판례로 내려가며 범위를 좁히는 탐색이 검토 업무의 대부분
2. **수치·기한 요건은 그대로 증명**, **평가적 요건은 가정**으로 두고 판례·예규를 그 가정의 경계로 붙인다
3. 출력은 참/거짓 2값이 아니라 **충족 · 위반 · 미확정 3값**. 미확정에는 "다투려면 무엇을 입증해야 하는가"를 붙인다
4. 법령은 시행일별 버전이 있으니 **적용 시점을 파라미터**로. 부칙·경과규정도
5. IMO 같은 국제 기준의 법상 위치 → **헌법 제6조 조약 우선순위**로 적용 순서 구조화

| `lean/LSA/Ch4.lean` | 제4장 근로시간: 통상/탄력/선택제, 연장, 휴게, 연차 |

### 파이프라인
```
사용자 문장 → [Solar Pro 4] 사실 추출 (Facts JSON)
           → [Lean 컴파일된 바이너리] judge : Facts → List Finding   (45ms)
           → [Solar] 결과 설명문
```
API: `POST /api/analyze {text, law, context}` → 스트리밍 JSONL (extract / judge / explain / result)

### 판정값
`inductive Status | ok | violation | needFacts | info`

### 핵심 메커니즘 — 미확정 사실의 전수열거
- 각 주제(`judgeHours`, `judgeDismissal`…)는 참조하는 Bool 사실 목록(`BoolFact`)을 갖고, 값이 `none`인 키 n개에 대해 **2^n 진리표를 전부 계산**
- 전부 적법 → ok / 전부 위법 → violation / 갈리면 → needFacts + **결론을 실제로 바꾸는 키(decisive)만 질문**
- 진리표는 n ≤ 5(32조합)일 때만 UI에 표시
- 수치 사실(분·일·원)은 없으면 바로 `needNumbers`로 질문

### 시점 처리
- `Facts.year/month` 기본값 2026/9. 벌칙 표(`sanction year month`)와 제53조③ 소기업 특례(2022.12.31 일몰)만 시점 분기. **시행일별 버전 구조는 없음**

### 열린 개념 처리 — 여기가 미아 제안과 갈리는 지점
- 코드 주석에 `[열린 개념: 입력]`으로 표시된 필드(긴박한 경영상 필요, 해고 회피 노력, 공정한 기준, 성실한 협의, 정당한 이유…)는 **전부 `Bool`**
- 즉 LLM이 문장에서 true/false를 찍으면 그대로 판정에 들어감. 판례·시행령은 사이트 스스로 "반영하지 않았다"고 명시

### 실측 (API 직접 호출, 2026-09-10)
| 입력 | 추출 결과 | 판정 |
|---|---|---|
| "20명 회사, 주5일 점심 없이 10시간" | regularEmployees 20, weekMinutes 3000, maxDayMinutes 600 | needFacts — 나이·휴게분 질문 (제50·54조) |
| "300명, 3년 적자·자본잠식, 30명 경영상 해고, 60일 통보·협의, 서면 30일 예고" | `urgentNeed: true`, goodFaithConsult true … | 해고 판정 **안 나옴** (`dismissed` 키가 안 채워짐) → 연차만 needFacts |
| "300명, 흑자인데 인건비 절감으로 해고, 60일 통보…" | `urgentNeed: false, avoidanceEffort: false, fairCriteria: false, noSexDiscrimination: false` | 역시 해고 판정 안 나옴 |

→ 두 가지가 보인다.
1. **평가적 요건을 LLM이 Bool로 결정**한다. "흑자+인건비 절감" 문장에서 회피노력·공정기준·성차별까지 false로 찍었다(문장에 없는 사실). 이게 판정에 들어가면 Lean 증명은 성립하지만 전제가 틀린 것
2. 추출 단계가 취약하다. `economicDismissal: true`는 잡으면서 `dismissed`를 안 채워 해고 주제 자체가 스킵됨

## 2. 구현 — `LeanLawExt.lean` (core Lean 4, 의존성 없음)

미아 제안을 사이트 구조 위에 얹는 형태로 별도 모듈 작성. 항목별 대응:

| 제안 | 구현 | 증명한 것 |
|---|---|---|
| 3값 출력 | `inductive Verdict \| satisfied \| violated \| undetermined` + Kleene `and`/`all` | `and_comm`, `and_violated_*`, `and_satisfied_iff`, **`and_mono`(증거를 더해도 확정 결론은 안 뒤집힘)**, `all_violated_of_mem`, `all_satisfied_iff` |
| 평가적 요건 = 가정 + 판례 경계 | `UrgentNeedEvidence`(Option 필드 4개) → `urgentNeedBoundary : … → Verdict`. 성립 패턴 2, 불성립 패턴 1, 나머지 미확정 | `urgentNeed_consistent`(무모순), **`urgentNeed_mono`**(증거 정제 단조성) |
| 미확정 + 입증 부담 | `urgentNeedBurden : … → List (방향 × 입증자료)` | `example`: 증거 4개가 다 있어도 경계 밖이면 미확정이면서 부담 목록이 **빈** 반례 존재 → "경계가 촘촘한가"는 Lean이 반례로 알려주지만 채워주진 못함 |
| 수치는 그대로 증명 | `art24_3 (days) := ofBool (days ≥ 50)` / `art24 := all [경계, 회피노력, 50일]` | **`art24_violated_of_short_notice`**: 49일이면 열린 개념과 무관하게 위반 확정 / `art24_satisfied_iff`: 충족은 세 요건 전부 확정일 때만 |
| 적용 시점 파라미터 | `Version α = {effectiveFrom : Date, rule}` / `pick vs at` = 시행일 ≤ at 중 최신 | **`pick_effective_le`**: 시행 전 법을 적용하는 일이 없다 |
| 부칙·경과규정 | `penaltyFor vs actAt judgedAt`: 행위시법 원칙, 신법이 가벼우면 신법(형법 제1조) | **`penalty_le_act`**: 적용 형벌은 행위시법을 넘지 않는다. 예시 3건 `decide` |
| 조약 우선순위 | `NormKind.rank`(조약 = 법률 동순위, 헌법 6조①) / `prevails`: 상위법 → 특별법 → 신법 | **`prevails_total`**: 어떤 두 규범이든 한쪽이 우선(판정 공백 없음). SOLAS vs 선박안전법 예시 |

컴파일 결과 (2026-09-10, Lean 4.33.1, 의존성 없음): **0 errors / 0 warnings, ~2.5초**. 541줄, `theorem` 22개.

실행: `elan` 설치 후 `lean LeanLawExt.lean` (Mathlib 불필요).

`#eval` 출력 (미아 메모 사례):
```
urgentNeedBoundary {적자 3년, 자본잠식}        → satisfied
urgentNeedBoundary {적자 0년, 인건비절감만}     → violated
urgentNeedBoundary {}                          → undetermined
urgentNeedBurden {}                            → [(성립, 연속 적자 재무제표), (성립, 자본잠식), (성립, 사업부문 폐지), (불성립, 인건비 절감 외 목적 없음)]
urgentNeedBurden {적자 1년}                    → 남은 세 가지만
art24 {사례①, 60일 통보, 회피노력 미확정}       → undetermined   ← 사이트라면 urgentNeed=true 로 그냥 통과
penaltyFor 2026-09 행위 / 2026-11 재판          → 3년·3천만 (행위시법)
```

## 4. 미아 질문에 대한 답 (09-10)

### Q1. "긴박한 경영상 필요"는 판례·예규가 들어가야 판단된다는 거고, 로직은 내 말대로 짠 거지?
맞다. 구조는 제안대로다 — `Bool` 입력 대신 증거 구조 → 판례 패턴 3개(`patA/patB/patC`) → 3값. **현재 패턴은 자리표시자**다. 실제로 필요한 데이터는:
- 대법원 판례 요지 (예: 계속된 적자·자본잠식·사업부문 폐지 → 성립 방향 / 흑자·단순 인건비 절감 → 불성립 방향)
- 고용노동부 행정해석·예규 (경영상 해고 신고 기준 등 시행령 제10조)
- 각 패턴에 판례 번호를 붙이는 작업

Lean이 해주는 것: 패턴끼리 모순 없음, 증거를 더 넣어도 확정이 안 뒤집힘, **증거가 다 있어도 결론이 안 나는 구멍**을 반례로 알려줌. Lean이 못 하는 것: 그 구멍을 판례로 채우기.

### Q2. "행위시법 안 넣음"이 행위 당시 법을 못 찾는다는 뜻인가? Lean으로 되나?
오해다. 행위시법은 **넣었고 증명까지 됐다**. `penaltyFor actAt judgedAt` 가 행위 시점 버전을 고르고, 재판 시점 신법이 더 가벼우면 신법(형법 제1조②)을 택한다. `penalty_le_act` 정리: 어떤 경우에도 행위시법보다 무겁게 처벌하지 않는다.
예시에서 `none` 이 나온 건 "2020년 행위인데 버전 표에 2021.11 이전 조문이 없어서 처벌 규정 없음" — 죄형법정주의상 맞는 출력이다. 즉 **Lean은 되고, 부족한 건 시행일별 조문 데이터**(국가법령정보센터 연혁법령을 버전 표로 옮기는 일).

### Q3. 규범 서열 — 근로기준법에 특별법·조약이 어떻게 얽혀 있나
```
헌법 (제32·33조 근로의 권리·노동3권, 제6조① 조약 = 국내법과 같은 효력)
 ├─ 조약: ILO 협약 (비준한 것만). 핵심협약 87·98·29호 2021.4.20 기탁 → 2022.4.20 발효
 │        105호(강제노동 폐지) 미비준. 해사노동협약(MLC 2006) → 선원법 전면개정(2011 통과, 2012 시행)
 ├─ 법률: 근로기준법 = 일반법
 │    특별법 (특별법 우선): 선원법(제5조 — 근기법 중 일부 조문만 선원에 적용, 나머지는 선원법)
 │                        국가·지방공무원법, 기간제법, 파견법, 남녀고용평등법, 최저임금법,
 │                        근로자퇴직급여보장법, 산업안전보건법, 노동조합법
 ├─ 대통령령: 근로기준법 시행령 (상시근로자 산정, 경영상 해고 신고 규모 등)
 ├─ 고용노동부령: 시행규칙
 ├─ 고시·예규·행정해석 (질의회시) — 법규성 없음, 실무 기준
 └─ 판례 (대법원) · 노동위원회 결정 — 규범 아님, 해석 자료
```
**조약과 근로기준법이 충돌하면**: 헌법 6조①로 동순위 → 특별법·신법 원칙. 다만 ILO 협약은 "자기집행력"(법원이 직접 적용 가능한지) 논쟁이 있어 실무는 국내법 개정으로 반영하고, 법원은 해석 기준으로 쓴다. 현재 `prevails` 는 순위+특별+신법만 보므로 **자기집행 여부 플래그가 하나 더 필요** — 다음 작업.

**해양 세미나와의 연결**: 선원 근로는 근로기준법이 아니라 선원법(MLC 이행법) — IMO/ILO 협약 → 선원법 → 시행령 → 해수부 고시 라인. 어제 박한선 박사가 말한 "IMO 협약은 글로 돼 있고 통일해석(UI)이 따로 있다"가 여기서 `precedent`/`rule` 층에 들어간다.

## 5. 한계 측정 — Lean으로 되는 것 / 안 되는 것

| 되는 것 (증명됨) | 안 되는 것 |
|---|---|
| 형식화 **내부**의 무모순·단조성·경계값·버전 선택 유일성 | 형식화가 실제 법·판례를 맞게 옮겼는지 (사이트도 명시) |
| 수치·기한 요건은 열린 개념과 무관하게 확정 | 열린 개념 자체 — 판례 패턴은 사람이 넣고, LLM은 제안만 |
| "증거가 다 있어도 결론이 없는 조합"을 반례로 제시 | 그 구멍을 채우기 |
| 행위시법·경과규정 보장 | 시행일별 조문 데이터 확보 |
| 규범 서열 판정에 공백 없음 | 조약 자기집행력 판단, 통일해석(UI)의 법적 지위 |
| 판정 45ms, 컴파일 2초 | LLM 사실 추출 단계의 오류(실측: 문장에 없는 사실을 false로 채움) — Lean이 못 막음 |

전수열거 비용: 미확정 Bool n개 → 2^n. 사이트는 n≤5만 진리표 표시. 제24조 요건을 전부 Bool로 두면 10~20개 → 10^3~10^6. 증거 구조로 바꾸면 열거 대신 패턴 매칭이라 이 비용이 사라짐.

## 7. 규범 서열 — 자기집행 플래그 추가 후 분기 (09-10 오후)

`Norm` 에 `selfExecuting : Bool` 추가. `resolve a b` 는 ① 직접 적용 불가(비자기집행 조약)인 쪽을 먼저 제외 ② 남은 것끼리 상위법 → 특별법 → 신법.

증명: `resolve_mem`(결과는 둘 중 하나), `resolve_skips_non_self_executing`(비자기집행 조약은 직접 적용 안 됨), `resolve_applicable`(적용 가능한 쪽이 있으면 결과도 적용 가능), `prevails_total`(우선순위 공백 없음).

| 사례 | 충돌 | 결과 | 왜 |
|---|---|---|---|
| 해양 (어제 세미나) | SOLAS 협약(조약·특별·자기집행 **가정**) vs 선박안전법(법률·일반·2024) | SOLAS | 동순위 → 특별법 우선. 법률이 더 최근이어도 같다 |
| | SOLAS vs 선박안전법 시행령 | SOLAS | 순위에서 결정 |
| 선원 근로 | 선원법(특별) vs 근로기준법(일반·2026) | 선원법 | 특별법 우선 |
| | MLC 2006(조약·**비자기집행**) vs 선원법 | 선원법 | MLC 는 이행법(선원법)을 통해서만 적용 |
| | (가정) MLC 가 자기집행적이었다면 | MLC | 플래그 하나가 결론을 바꾼다 — 이 판단이 법률 검토 사항 |
| 노동 | ILO 87호(2022 발효·비자기집행) vs 근로기준법 | 근로기준법 | 현 실무(법원은 해석 기준으로만) |

## 9. 쉬운 말로 — 이 실험이 말하는 것 (09-10 저녁, 미아 질문 정리)

### Lean 은 뭘 하는 도구인가
"규칙표가 주어지면 그 표대로 낸 결론은 절대 안 틀린다"를 보장하는 도구. 계산기와 같다 — 계산은 확실하지만 어떤 식을 넣을지는 사람이 정한다. 여기서 "식"은 판례 경계, 시행일별 조문, 조약 자기집행 여부.

### 사이트의 Bool 문제가 왜 제안과 연결되나
Lean 이 증명하는 건 "**만약** 긴박한 필요 = true 이고 통보 50일 이상**이면** 적법"이다. 앞의 "만약"을 지금 사이트는 LLM 이 채운다. 그래서 "흑자인데 인건비 절감" 한 문장에서 회피노력·공정기준·성차별까지 false 로 찍었다 — 문장에 없는 걸 지어낸 것. Lean 은 지어낸 전제 위에서 정확히 계산했을 뿐이라 결론이 틀린다.

제안대로 바꾸면 LLM 은 **판단을 못 하고 사실만 채운다**. "적자 연수 = 0, 인건비 절감 목적 = 예" 같이 문장에 실제로 있는 것만 넣고 없는 건 빈칸. 판단은 코드 안의 판례 패턴이 하고, 빈칸이 남으면 미확정 + 입증 목록. 막힌 지점은 제안이 아니라 **LLM 에게 판단까지 시킨 것**이다.

### 사람이 넣어야 하니 Lean 강점이 죽는 것 아닌가
아니다. 사람은 판례 경계를 **한 번** 쓰고, 그 뒤 수천 건 판정은 Lean 이 같은 기준으로, 모순 없이, 시행일 맞춰서, "이 판정은 어느 패턴·어느 조문에서 나왔다"를 추적 가능하게 낸다. LLM 만 쓰면 같은 사건도 돌릴 때마다 답이 흔들리는데 그게 없어진다.

### 핵심 — 사람이 놓친 빈 곳을 Lean 이 사례로 지목한다
판례 패턴 3개를 넣었다.
- 성립 A: 적자 2년 이상 + 자본잠식
- 성립 B: 적자 1년 이상 + 사업부문 폐지
- 불성립 C: 적자 0년 + 인건비 절감만 목적

이 세 개로 다 판정될 것 같지만, **적자 1년 · 자본잠식 아님 · 폐지 없음 · 인건비 절감만도 아님** 은 어디에도 안 걸린다. 증거 네 개가 다 확인됐는데 미확정이고, 더 물어볼 것도 없다. 이게 구멍.

Lean 에 "증거가 다 채워지면 반드시 충족이나 위반이 나온다"를 증명하라고 시키면, Lean 이 "아니요, 이 조합에서는 안 됩니다"라고 **위 사례를 내놓는다** (코드의 `example : ∃ e, urgentNeedBoundary e = .undetermined ∧ urgentNeedBurden e = []`). 사람이 판례 20건 읽고 패턴을 짜면 반드시 생기는 누락을 이렇게 하나씩 잡는다. 채우는 건 판례를 더 찾아 패턴을 추가하는 사람 일.

→ 프레임: Lean 은 "규칙표 계산기"이면서 동시에 **"규칙표의 빈칸 검사기"**. 썽킴이 처음 말한 "LLM 자연어에 Lean 검증을 더하면 차별성"이 실제로 나오는 지점이 여기다.

### 판례를 알아야 Lean 화가 되나
요건 종류에 따라 다르다.
- **수치·기한 요건**(50일 통보, 30일 예고, 벌금 상한): 조문만 있으면 끝. 판례 불필요
- **평가적 요건**(긴박한 필요, 회피 노력, 공정한 기준): 조문에 숫자가 없어서 판례가 반복해서 보는 요소(적자 연수, 자본잠식, 폐지 여부)를 뽑아야 수치·서류로 바뀌고 그게 패턴이 된다. 판례를 모르면 미확정으로만 남는다

### 판례 경계, 뭘 먼저 넣나
기준 셋: 사용자 질문에 자주 나오는 요건 / 대법원이 같은 요소를 반복해서 보는 요건 / 그 요소가 서류·수치로 확인되는 요건.

경영상 해고 기준 순서:
1. **긴박한 경영상 필요** — 판례 많고 요소 안정적(연속 적자·자본잠식·사업부문 폐지·매출 급감), 재무제표로 확인. 지금 코드의 자리표시자
2. **해고 회피 노력** — 희망퇴직·배치전환·근로시간 단축 시행 여부로 비교적 정형화
3. **합리적이고 공정한 기준** — 사안별로 갈려 패턴화 어려움. 나중에
4. **성실한 협의** — 회의록·통보 일자는 수치화되지만 "성실"은 남음. 맨 뒤

1번 하나만 대법원 20건으로 채워 돌려보면 이 방식이 되는지 판가름 난다.
